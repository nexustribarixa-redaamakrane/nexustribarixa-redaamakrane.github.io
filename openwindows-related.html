OpenWindows & Related IN DEV

OpenWindows Kernel & Ecosystem Architecture

OpenWindows & Related is a low-level operating system software suite built with freestanding C99 (-std=c99 -nostdlib -ffreestanding) and NASM assembly. It comprises the OpenWindows kernel plus its bootloader, storage, driver/DLL and SuperUnicode companion libraries. OpenWindows is an experimental developer preview focused on VM and host-test development — it is not a production OS.

Core Sub-Projects

  • OpenWindows Kernel: OpenWindows GitHub Repo — Experimental freestanding x86-64 kernel and OS prototype: x86-64 boot, IDT and interrupt handling, UART/VGA console, keyboard, PIT/PIC and selected ACPI power paths, static process/thread tables with single-CPU round-robin scheduling, Ring 3 to Ring 0 syscalls over the kernel-owned int 0x80 ABI, OWFS/USFS through a VFS facade, runlevels -6 through 6, and a CIS verification pipeline for signed OWX images.
  • Modular Bootloader (MBL): Modular-Bootloader GitHub Repo — Freestanding 64-bit UEFI bootloader (BOOTX64.EFI) that boots from a GPT disk with a FAT32 ESP and hands control to the 32-bit OpenWindows kernel at 0x200000. Features a GRUB-style text boot menu rendered on the UEFI Graphics Output Protocol (GOP) framebuffer with an embedded 8x16 CP437 font (BGRA/RGBA) and a 10-second countdown fallback, an integrated OpenWindows File System (OWFS) driver, UEFI Block I/O sector access, and SuperUnicode (SUCS / SUTF) boot configuration transport.
  • OpenWindows Storage (ow-storage): OpenWindows-Storage GitHub Repo — Storage and block abstraction static libraries: libowfs.a (Native OpenWindows File System) and libusfs.a (Universal Secured File System). SUTF-8 paths and volume labels mapped to SuperUnicode 31-bit codepoints. Features a Hardware Translation Layer (HTL) tagged for NVMe, AHCI/SATA and USB mass-storage endpoints, CRC32c/Fletcher-64 checksums, power-cut dirty-state locking with mandatory consistency scans, ChaCha20 data-at-rest encryption (256-bit key, 12-byte per-volume nonce, 64-byte blocks), CRC32c entry-table signing in USFS, an identity-based ow_sec access model, and 3-pass cryptographic purge / full scrub sanitization.
  • OpenWindows-Essentials: OpenWindows-Essentials GitHub Repo — Core driver, dynamic library, file-format and recovery infrastructure: .owc drivers, .owd dynamic libraries and .sentinel recovery directives, the Damage Control Sentinel repair engine, and the ow* user-mode suite including the required PID 1 orchestrator owinit.
  • vip (Volume Indexing Protocol Framework): vip GitHub Repo — Freestanding C99 static library (libvip.a) providing the ecosystem's foundational indexing layer: FVIP fixed-capacity file index tables with SUTF-8 path validation, hashing and integrity verification, plus UniVIP, a 44-bit sparse hex trie (11 nibbles deep, up to 16 children per node) giving O(11) path lookup with zero dynamic allocation.
  • BANcode Framework: BANcode GitHub Repo — Diagnostic code framework for bare-metal OS kernels defining four categories — BANcode (fatal errors), WARNcode (warnings), COMcode (communication events) and SOFTcode (soft recovery) — with generated C99 freestanding headers and implementation, a Rust no_std crate and a Python package, all produced from a single source registry.
  • SuperUnicode (SUCS / ExtSUCS): Character Encodings — Bare-metal C99 implementation of the SuperUnicode character encodings and the SUTF transformation formats / SUST serialization transports the rest of the ecosystem speaks.
